# Photo Score

사진의 픽셀을 브라우저에서 분석해 **7개 항목 점수, 종합 점수, 등급, 촬영·후보정 팁**을 제공하는 웹 도구입니다. 로그인이나 API 키 없이 로컬 사진을 불러와 사용할 수 있습니다.

소개 페이지에서는 “AI”라는 표현을 사용하지만, 현재 구현의 핵심은 히스토그램·에지·색 분포·선명도 등의 **수치와 규칙에 기반한 평가**입니다. 외부 생성형 AI API나 학습된 모델을 호출하는 방식은 아닙니다.

## 주요 기능

- JPG·PNG·WebP 등 브라우저 지원 이미지의 드래그 앤 드롭
- 구도·노출·피사체·보케/심도·색감·선명도·창의성 평가
- 100점 기준 종합 점수와 등급 표시
- 측정값과 점수에 따른 상세 개선 제안 및 퀵 팁
- 감지한 구도와 추정 피사체 위치를 표시하는 SVG 오버레이
- 새 사진 선택과 재분석

별도 백엔드나 패키지 설치·빌드 과정이 없습니다. 화면과 분석 코드는 `index.html` 안에 함께 들어 있습니다.

## 실행 방법

GitHub의 **Code → Download ZIP**으로 내려받아 압축을 풀고 `index.html`을 브라우저에서 여세요.

Git과 Python 3가 설치되어 있다면 로컬 서버로 실행할 수 있습니다.

```sh
git clone https://github.com/Velvitty/Photo_Scorer.git
cd Photo_Scorer
python3 -m http.server 8000 --bind 127.0.0.1
```

- 프로그램: <http://localhost:8000/index.html>
- 소개·사용 안내: <http://localhost:8000/manual.html>

## 사용 방법

1. 사용권 계약서의 체크 항목을 확인하고 **동의하고 시작하기**를 누릅니다.
2. 업로드 영역을 클릭하거나 사진 한 장을 끌어다 놓습니다.
3. 미리보기를 확인하고 **분석 시작**을 누릅니다.
4. 종합 점수와 항목별 점수, 구도 표시 및 개선 팁을 확인합니다.
5. **다시 선택**으로 다른 사진을 불러와 비교합니다.

사진을 자동으로 보정하거나 원본을 덮어쓰는 도구는 아닙니다. 제공되는 팁을 참고해 촬영 또는 별도 편집 도구에서 수정한 뒤 다시 분석할 수 있습니다.

| 구분 | 현재 구현 |
| --- | --- |
| 입력 단위 | 한 번에 이미지 1장. 여러 파일을 드롭해도 첫 번째 파일만 사용 |
| 파일 판별 | MIME 타입이 `image/`로 시작하는지 검사하고 브라우저 디코더로 읽기 |

| 분석 픽셀 | Canvas의 RGBA 데이터에서 RGB를 사용하며 알파값은 점수 계산에서 제외 |
| 실행 위치 | 메인 스레드의 동기 JavaScript 연산. Web Worker·GPU 추론 사용 없음 |

| 점수 범위 | 표시 척도는 100점. 각 항목은 반올림 후 상한 97점, 하한 10점으로 제한하며 피사체·창의성 하한은 15점 |

축소 비율은 `min(800 / max(원본 너비, 원본 높이), 1)`이고, 너비·높이는 각각 반올림합니다. 예를 들어 6000×4000 이미지는 800×533 캔버스에서 분석합니다. 결과 화면의 사진은 원본 Data URL을 사용하므로 분석 해상도와 표시 이미지의 원본 해상도는 다릅니다.

## 기술 문서: 측정과 채점

### 노출과 히스토그램

각 픽셀의 휘도는 `round(0.299 × R + 0.587 × G + 0.114 × B)`로 계산합니다. 별도의 선형광 변환이나 카메라 센서 데이터 분석은 수행하지 않습니다.

- 휘도 0~255를 256개 히스토그램 구간으로 집계하고 평균 밝기와 표준편차를 구합니다.
- 암부 클리핑은 0~7, 명부 클리핑은 248~255 구간의 픽셀 비율입니다.
- `dynamicRange`는 누적 히스토그램의 약 95백분위 휘도에서 5백분위 휘도를 뺀 값입니다. 센서의 다이내믹 레인지나 스톱 수가 아닙니다.
- 노출 기본점수는 50점입니다. 평균 밝기와 128의 상대 편차가 0.1/0.2/0.35 미만이면 각각 30/25/15점을 더하고, 그 밖에는 편차의 25배를 뺍니다.
- 암부·명부 비율의 150배를 각각 최대 15점까지 감점합니다. 명암 범위가 180 초과면 12점, 120 초과면 8점 가점하고 60 미만이면 8점 감점합니다. 휘도 표준편차가 35 초과·85 미만이면 8점을 더합니다.

### 구도 에너지 맵

이미지를 **9×9, 총 81개 셀**로 나누고 각 셀 안을 가로·세로 3픽셀 간격으로 샘플링합니다. 한 지점의 에너지는 오른쪽·아래 이웃 픽셀과의 휘도 차이 절댓값 합이며, 셀별 평균으로 에너지 맵을 만듭니다.

| 패턴 | 측정 방식 |
| --- | --- |
| 삼분법·황금비율 | 각 교차점 주변 셀 에너지를 전체 평균과 비교. 두 패턴 중 높은 것 하나만 최종 후보에 포함 |
| 나선형 | 미리 정한 나선 근사 위치의 에너지 평균 비교 |
| 대각선 | 양쪽 대각선을 따라 샘플링한 값 중 높은 값 사용 |
| 중앙집중 | 중앙 주변 셀의 평균 에너지 비교 |
| 사다리꼴 | 중앙 열 집중도와 위·아래 행 에너지 비율 결합 |
| 대칭·균형 | 좌우 대응 셀 차이와 좌우·상하 에너지 합 비교. 별도 보너스·감점에 사용 |

기본 20점에 최상위 패턴 최대 32점, 두 번째 패턴 최대 12점, 대칭 최대 8점, 균형 가점을 더합니다. 에너지가 지나치게 균일하거나 패턴이 약하고 한쪽으로 치우치면 감점합니다. 최종 패턴 점수는 확률이나 신뢰도가 아니라 **평균 대비 에너지 집중도 계열의 상대 지표**입니다.

### 선명도, 피사체, 보케 추정

전체 선명도 `avgSharpness`는 가장자리를 제외한 영역을 2픽셀 간격으로 순회하면서 `abs(4 × 중심 휘도 − 위 − 아래 − 왼쪽 − 오른쪽 휘도)`를 평균한 값입니다. 라플라시안 응답의 절댓값 평균이며, 라플라시안의 분산을 계산하는 방식은 아닙니다.

선명도 점수는 25점에서 시작합니다. 평균 응답이 3/5/7/10/15를 초과하면 각각 22/35/45/55/65점을 더하고, 12 초과에서는 8점을 추가합니다. 35를 넘는 극단적인 값에는 최대 15점의 노이즈 관련 감점을 적용합니다.

피사체·보케는 별도로 **7×7, 총 49개 셀**을 사용합니다. 각 셀의 값은 2픽셀 간격으로 샘플링한 오른쪽·아래 휘도 차이의 평균입니다.

1. 선명도 상위 약 12%인 **6개 셀**을 피사체 후보로, 하위 약 20%인 **10개 셀**을 배경 후보로 선택합니다.
2. 후보별 평균으로 `subjectSharp`와 `bgSharp`를 계산합니다. 배경 값이 0.05보다 크면 `subjectContrast = subjectSharp / bgSharp`이고, 그 이하는 0 나눗셈을 피하는 별도 분기를 사용합니다.
3. 전체 셀 평균의 1.15배보다 선명한 셀 비율을 `sharpAreaRatio`, 셀 선명도의 표준편차/평균을 `sharpCV`로 계산합니다.
4. 피사체 점수는 분리비, 선명도 변화, 선명 영역 비중, 중앙 에너지와 피사체 선명도를 조합합니다. 보케 점수는 분리비, 배경의 절대 선명도, 피사체·배경 차이와 선명 영역 비중을 조합합니다.

빨간 사각형은 선택된 6개 셀의 **중심 위치**입니다. 물체의 윤곽·얼굴·눈 또는 실제 초점면을 검출한 바운딩 박스가 아닙니다.

### 색감, 창의성, 종합 점수

색감은 RGBA 배열을 16바이트씩 순회해 약 4픽셀마다 한 번 샘플링합니다. HSV 계열 채도와 30도 단위의 **12구간 색조 히스토그램**을 계산하며, RGB 최대·최소 차이가 0.05보다 큰 샘플만 색조 집계에 포함합니다. 전체 샘플 수의 2%를 넘는 구간을 활성 색조로 셉니다.

색감 점수는 평균 채도, 활성 색조 수, 인접 색조의 연속성, 채도 표준편차를 결합합니다. 매우 낮은 채도의 단색 이미지에는 45점의 하한 보정을 적용합니다. 창의성 점수는 종횡비, 색조 수, 대비, 밝기·채도 조합, 대칭, 피사체 분리와 채도 변화를 합친 규칙입니다.

```text
종합 = round(구도×0.25 + 피사체×0.20 + 노출×0.15 + 색감×0.15
             + 선명도×0.10 + 보케×0.10 + 창의성×0.05)
```

각 항목 상한이 97점이므로 현재 산식에서 100점은 나오지 않습니다. 같은 픽셀과 같은 코드에서는 점수가 결정되지만, 브라우저의 디코딩·캔버스 축소 결과가 달라지면 경계값 근처의 점수도 달라질 수 있습니다.

## 기술 문서: 결과 데이터와 화면 구성

`analyzeImage(canvas)`는 다음 형태의 JavaScript 객체를 반환합니다. 공개 HTTP API나 파일 저장 형식이 아니라 화면 렌더러가 사용하는 내부 데이터 계약입니다.

| 필드 | 자료형·의미 |
| --- | --- |
| `composition`, `exposure`, `subject`, `bokeh`, `color`, `sharpness`, `creativity` | 정수, 항목별 점수 |
| `overall` / `summary` | 정수 종합 점수 / 강점·보완 항목을 담은 문자열 |
| `detailed_tips` | `{ title, description }` 객체 배열 |
| `quick_tips` | 우선순위로 정렬된 팁 문자열 배열, 최대 12개 |
| `meta.meanBrightness`, `meta.dynamicRange` | 숫자, 평균 휘도와 백분위 휘도 차이 |
| `meta.avgSaturation`, `meta.sharpAreaRatio` | 백분율로 변환한 문자열. 각각 소수점 1자리 / 정수 표시 |
| `meta.avgSharpness`, `meta.bgSharp`, `meta.subjectSharp` | 소수점 1자리의 문자열 |
| `meta.subjectContrast`, `meta.sharpCV`, `meta.compBest` | 소수점 2자리의 문자열 |
| `meta.compPattern`, `meta.compScore2` | 1위·2위 패턴 이름. `compScore2`도 숫자가 아닌 이름 |
| `meta.compPatterns` / `meta.symmetryScore` | 점수순 `{ name, score }` 배열 / 소수점 2자리로 반올림한 숫자 |
| `meta.subjectPositions` | `{ x, y }` 배열. 이미지 너비·높이 기준 0~100 좌표 |
| `meta.imgW`, `meta.imgH` | 분석 캔버스의 픽셀 크기 |

히스토그램·에너지 맵·원시 클리핑 비율은 계산 중에 사용되지만 반환 객체에 모두 포함되지는 않습니다. 소수점 표시용 문자열을 다시 수치 계산에 쓰려면 숫자로 변환해야 합니다.

## 데이터 처리와 해석상의 한계

- 사진은 브라우저 메모리에서 분석합니다. 분석을 위해 원격 서버에 사진을 업로드하거나 계정을 만드는 기능은 없습니다.
- Google Fonts 로딩에는 네트워크 요청이 발생하므로 “로컬 분석”이 웹 페이지의 모든 요청이 없다는 뜻은 아닙니다.
- 점수는 사진을 연습하고 비교하기 위한 참고 지표입니다. 작품의 의미·스토리·촬영 의도나 예술적 가치를 객관적으로 판정하지 않습니다.
- 피사체와 심도는 픽셀의 선명도 분포로 추정합니다. 사람·사물의 의미를 인식하거나 실제 거리·조리개 값을 측정하지 않습니다.
- 800px 축소, 이미지 압축, 노이즈, 강한 후처리에 따라 결과가 달라질 수 있습니다. 보케를 의도하지 않은 풍경·기록 사진은 해당 항목이 낮아도 결함을 뜻하지 않습니다.
- EXIF의 카메라·렌즈·ISO·셔터속도·조리개 값은 읽지 않습니다. 개선 팁에 나오는 촬영 수치는 실제 촬영 정보의 측정값이 아닌 규칙에 따른 제안입니다.
- 분석용으로 줄이기 전에 원본을 Data URL로 읽고 디코딩하므로 대용량 파일의 메모리 사용까지 800px로 제한되지는 않습니다. 파일 크기 상한·최소 이미지 크기 검증도 별도로 구현되어 있지 않습니다.
- 현재 팁 생성에 전달되는 내부 `meta`에는 `compPattern`, `compBest`, `satStd`가 빠져 있어 일부 구도 패턴·채도 변화별 조언 조건이 충족되지 않습니다. 결과 객체와 SVG에는 구도 정보가 별도로 전달됩니다.
- 투명 이미지, 극소형 이미지, 디코딩 실패에 대한 전용 분석·복구 UI는 없습니다. 사진 형식의 일반적인 불투명 이미지를 사용하는 편이 적합합니다.

## 문제 해결

- 업로드가 되지 않으면 JPG·PNG·WebP로 변환해 다시 시도하세요. RAW·HEIC 등의 디코딩 지원은 브라우저에 따라 다릅니다.
- 분석이 지연되면 큰 원본을 줄인 복사본으로 시도하고 다른 메모리 사용량이 큰 탭을 닫으세요.
- 세부 점수와 추천이 기대와 다르면 사진의 촬영 의도와 측정 지표를 함께 보세요. 점수를 높이기 위한 보정이 항상 더 좋은 사진을 만드는 것은 아닙니다.
